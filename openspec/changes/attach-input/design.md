# Design: attach-input

The terminal cannot hand an image to a program as text. Everything below is
a bridge over that fact; each path ends in the same value: a
`pendingAttachment` that `attachments.resolveAttachments` already knows how
to turn into transport parts.

```go
type pendingAttachment struct {
    Token string // "[img-1]" / "[shot.png]"
    Path  string // cache file (clipboard) or the dropped path
}
```

`pendingAttachment` lives in `tuiModel` next to `input textarea.Model`; it
is **not** part of `Turn.History`. On submit, tokens present in the text are
resolved to paths, the paths go through the resolver, and the resulting
`AttachmentRef`s ride the turn (see `attachments/design.md` §1).

## 1. Tokens

- Clipboard image: `[img-<n>]`, numbered per composer, reset on submit.
- File: `[<basename>]`, exactly as dropped (spaces preserved inside the
  brackets). Duplicate basenames get `[name-2.png]`.

Resolution is by map lookup, not by filesystem parsing: `[README.md]` typed
by hand (or generated by a model) is left verbatim unless a pending entry
with that exact token exists. Tokens are matched with a plain
`strings.Contains` scan over the text; regex only for masking when
reconciling.

## 2. Paste

Bubble Tea delivers `tea.KeyMsg{Type: KeyRunes, Paste: true, Runes: …}`.

- **Path pastes** (drag-and-drop): split on newlines, trim, strip wrapping
  single/double quotes and `file://`, unescape backslash-escaped spaces and
  parentheses terminals add (`My\ Shot.png`). If *every* non-empty line is an
  existing regular file or dir, register chips and insert only the tokens
  joined by spaces. If only
  *some* lines are paths (mixed prose + path), insert text unchanged —
  guessing there surprises people.
- **Empty/whitespace paste**: some terminals send nothing for an image
  clipboard. Treat as a clipboard-image attempt (same as ctrl+v).
- Anything else: today's behavior (insert literal text).

`Paste` is already special-cased in `tui_key.go` (mouse-fragment hold
bypass); keep that.

## 3. Clipboard image bridge

No cgo, no dep: run one external command, 3s timeout, stdout capped at
`[attachments] max_bytes` (20 MiB) + 1 byte to detect overflow.

| OS | command |
| --- | --- |
| darwin | `pbpaste -Prefer png` |
| linux, Wayland (`WAYLAND_DISPLAY` set) | `wl-paste --type image/png --no-newline` |
| linux, X11 | `xclip -selection clipboard -t image/png -o` |

First command found on PATH wins; probes are attempted in order, a non-zero
exit or empty stdout falls through to the next. Result is sniffed
(`attachments` magic bytes) — a `pbpaste` that returns the text form of a
file path is handled as the paste-path case instead. Capability is probed
once and remembered; on a miss, the notice names what to install
(`wl-clipboard`, `xclip`) on Linux.

`execCommand` is a package-level `var` (`func(name string, args ...string)
(string, error)`) so tests stub it; the TUI never routes this through the
sandboxed `shell` tool (that would need network/permission gates for a local
read).

## 4. Cache

Clipboard bytes need a path for the resolver:

```
$XDG_STATE_HOME/valen/attachments/<sha256>.<ext>   (0700 dir, 0600 file)
```

Content-addressed, so pasting the same screenshot twice costs one file.
Pruning: at TUI boot, delete files older than 7 days (one `ReadDir`, cap
200 entries). Cache write failure → notice, no attachment; never fails the
turn.

## 5. Composer UI

Above the chatbox, one dim line when non-empty:

```
attach: [img-1] 1280x720 84 KiB · [shot.png] 12 KiB
```

Backspace over a token deletes text only; the chip line is re-rendered from
the text on every keystroke, so a token with no text left disappears before
submit. Esc twice cancels; `/clear` and submit reset `pendingAttachment`.

Reconciliation at submit: for each pending entry, if its token is absent
from the trimmed text, drop it. If all tokens were dropped, behave like a
plain send.

## 6. Headless

`-f` already attaches paths. Tokens in `-p` text are literal (there is no
clipboard in a pipe). `-p` with a TTY and `-q` get the same composer, so
`-q` inherits paste support for free.

## 7. Persistence

Pasted images are turn-scoped like every attachment: `[img-1]` survives in
`Prompt` and JSONL, the bytes do not. A resumed session shows the token with
no image; the model simply does not see it again. Text attachments are
inlined in the prompt and therefore persist (existing `attachments` caps
apply).
